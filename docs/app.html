A live rendering of the app's views, built from its own design tokens. Not a screenshot: the numbers are sample data.

What's in itsix views, one question each

Each screen answers one plain question.

Five of them read and one writes. Everything shown comes from the JSONL files hyctl already writes to ~/.hydra, so the numbers on screen are the same ones hyctl cost and hyctl stats print, by construction. Settings is the exception, and the only file it touches is config.toml.

Chat

Ask, and see what answered

The window opens here. Ask anything and the reply names the model and the cost, with the run narrating itself as it goes rather than after. The model picker groups by shared quota, so it shows when choosing one model spends the budget another will need.

Models

What you can actually route to

Every model this machine found, grouped by the token pool it spends. Each is marked with whether it can be used right now and, when it cannot, why: no API key, or a local server that is not running. Beside it is the accuracy each model has actually earned, never shown without the number of outcomes behind it.

Usage

Where the money went

Spend grouped by model and by day, with call counts beside each, alongside context use and each model's checked record, so cost and accuracy sit on one screen.

Activity

What needs you

Every request, grouped by who has to act rather than by time alone: waiting on you, running now, something failed, done. A flat newest-first list gave a parked request, a live one and a month-old success the same weight, so nothing read as needing attention.

Session

Why it did that

Opened from a request in Activity, not from the rail.

One run's timeline in order: which model was selected, which candidates failed and why it fell through, how long each step took, where it handed off, and a layered graph when the run fanned out, so a swarm reads as a shape rather than a list. Its Code tab carries the diffs for the same run, marking what changed within a modified line, not just which lines moved, and lets you accept or undo the change on disk. Clicking a file in the graph opens it there.

Settings

What this machine is set to do

The switches that decide where work may go and what gets kept: PII sent only to a local model, refusing rather than sending when no local model is ready, whether prompt text and vectors are stored at all, and whether an answer may come from a previous run. Each one says what it costs rather than only what it is named, because every one of them is off by default for a reason. A config it cannot parse is reported, never rendered as defaults and never saved over.

Audit

What it was allowed to touch

Every tool call an agent made, whether the guardrails allowed it, and what got blocked or flagged, over an append-only, hash-chained audit log, mapped against the OWASP LLM Top 10. Its MCP servers tab carries a safety verdict for each server installed on this machine, and says plainly when nothing has been compared against the official registry yet.

Beside the chat, a pane you glance at. The model working now and the quota it draws from, how likely this run's answer is to be correct, the files it changed, and how accurate each model has measured at this kind of work, with the sample size beside every score, because a number from five observations is not a measurement.
The shape of itlocal by construction

No account. No Hydra server. Your logs stay on your machine.

There is no Hydra backend to sign in to, because there is no Hydra backend. The app opens the same files on your disk that the CLI writes, and that is the whole data path. Close it and the CLI keeps working exactly as before: the app is a window onto Hydra, not a dependency of it.

Same numbers

Agrees with the CLI

Both read cost.jsonl. A figure that differed between them would be a bug, and there is a test that says so.

Provider-neutral

Whatever you have installed

An OpenAI or Gemini key, a CLI agent, a local Ollama model: the app shows whichever models your machine actually has, and marks the ones it cannot use.

Estimated vs measured

Labelled, never conflated

Where a provider reports real token usage it says so; where Hydra estimated it, it says that instead. A guess is never shown as a measurement.

Downloadfree · MIT · no sign-up

One command on macOS and Linux.

It resolves the newest release, checks the download against the SHA-256 published beside it, and refuses to install on a mismatch. Nothing runs as root and nothing is written outside your applications directory.

$ curl -fsSL https://raw.githubusercontent.com/ankit373/hydra/main/install-app.sh | sh
  Release : v1.8.0
  Target  : darwin_universal
  Checksum: verified
  Installed: /Applications/Hydra.app

Pin a version with HYDRA_VERSION=v1.8.0, or change where it lands with HYDRA_APP_DIR=~/Applications. Read the script before you pipe it to a shell. It is under 200 lines, and you should.

Opening Hydra on a Mac for the first time. Hydra is not yet notarised by Apple, so the first time you open a copy you downloaded yourself, macOS says it cannot check Hydra and offers only Done or Move to Trash. Choose Done, then:
  1. Open System Settings and choose Privacy & Security.
  2. Scroll down to Security. Next to the message about Hydra, click Open Anyway.
  3. Confirm with your password or Touch ID. macOS remembers this, so you only do it once.
If macOS instead says Hydra is damaged, the download did not arrive whole: delete it, download it again, and open the zip by double-clicking it in Finder. The install command above does all of this for you. You can check any download against its sha256 link.
Nothing else to install. The app runs Hydra itself. On first launch it asks you to connect an AI model, either a key from a provider you already use or a free model on your own computer, and then answers a sample question. Developers who also want Hydra in a terminal can add the hyctl command-line tool from the app's Settings, or with the other install paths.
