The math, drawnhow the router decides

Three curves that run the router.

Hydra picks from each model's measured record, stops asking for more evidence once the answer clears your target, and for code, reads the dependency graph to know when a change is risky. Here is the math.

a · cost vs quality

The Pareto frontier

Single models are dots. Routing each task to the model best suited to it reaches equal or better quality at lower cost than any one of them, because the choice is made per task.

Matching a top model's quality at lower cost is the published RouteLLM result; Hydra applies the idea per request.
b · optimal stopping

Check, then stop

Hydra asks models one at a time until the sequential test (SPRT) says the answer is correct with your target probability. Then it stops and skips the models it no longer needs.

Fewer calls, bar cleared: a stated probability you can audit against outcomes.
c · percolation-κ

Blast radius (Molloy-Reed)

κ = ⟨k²⟩/⟨k⟩. A hub file with many transitive dependents is cascade-capable, so an edit to it must clear a higher bar. Hover a node.

High-κ ⇒ higher bar. The required probability rises with the graph.

Accountabilitycounts hide the sequence

You gave an agent access. What did it do?

Every access an agent makes is recorded in a local, hash-chained ledger. hyctl security reads that log and answers the one question you actually have, not a wall of metrics.

$ hyctl security
VERDICT ACT NOW
critical incident, gpt-4o: the same resource was denied
repeatedly, then it escalated to an exec/network action,
then it targeted the audit trail itself.
recon → escalation → audit-tampering · 4 event(s)
 
activity 4 blocked · 0 flagged
evidence 4 event(s), 4 hash-chained, intact

“4 denied, 2 flagged” and “injection → recon → escalation → an attempt on the audit trail” are the same rows read twice. Only the second one is an incident. Severity is OWASP Risk Rating (likelihood × impact), never a blended score.

How the verdict is computed, and what it refuses to claim

hyctl security --why opens the whole programme underneath: a risk register on an SLA clock, crosswalked to OWASP LLM / NIST AI RMF / ISO 42001 / MITRE ATLAS / SOC 2 · OWASP LLM Top-10 coverage · a policy audit that finds rules which can never fire · PII exposure resolved against real models, so a local model is not reported as a leak · control effectiveness, where a control that is configured but never applied reads as inert rather than as protection · CLI agent binary integrity · edit blast radius.

And the limit no percentage can state, printed in words on the default view: a CLI agent that Hydra sends work to is itself an agent, in a process Hydra does not control. The score covers what Hydra sends and records, not what such an agent independently reads and ships. Only a local-only run keeps the whole task on your machine.

Honest about its own limits. Framework mappings are marked curated assertions, not measurements. Defect cost is per-occurrence, not annualised. A file the dependency graph does not index is unknown, never “low-risk”. The attestation is unsigned, because Hydra has no key management and a signature without one is theatre.

That covers the agents. The other half is the machine they run on: Hydra discovers local model servers, ranks them and sends real work to them, so their configuration is part of its posture too. It checks them rather than assuming.

$ hyctl security --why --advisories

address is not loopback, so the server is serving more than this
machine, and neither Ollama nor vLLM requires auth by default

Ollama ships with no authentication and prints no warning when bound to 0.0.0.0. A model server answering the network is the one thing that falsifies local-first outright, and nothing was looking. The probe compares the same identity endpoint discovery already uses, between loopback and this machine's own addresses, so nothing goes on the wire and an unrelated listener on the same port is not mistaken for the model server.

What the machine scan proves, and what it cannot

A fix you don't have is not the same as no fix at all. Advisories are split on it, because a fully current Ollama still carries nine with no fix upstream: one combined count would read identically on a patched server and an abandoned one, and a number that fires when you have already done everything available to you is a number people learn to ignore. Fixable ones name the version to upgrade to. Unfixed ones say plainly that no upgrade answers them and point at the mitigation that exists, which is not reaching the server.

The negative result is the weaker one, and says so. A host firewall that drops the probe looks exactly like a server that is not listening, so loopback only is reported as weaker evidence than exposed. A machine with no non-loopback address ruled nothing out. A lookup that failed is unchecked, never clean. The advisory query is the only part of the whole report that leaves your machine, so it is off unless you ask for it.

Including its own state directory. The report had always said the CLI agent binary baseline is forgeable by anything able to write ~/.hydra, and nothing read a permission bit. Writable is the finding, since that is where the integrity baseline and the ledger's chain anchor live as plain files; readable is reported separately, since it exposes the listing and not the contents. It repairs nothing: the report is a read.

The ledger records what an agent did. hyctl mcp registry scores whether the MCP server it was talking to was ever safe to run in the first place. Every existing MCP directory answers “does this exist”; none answer “is it safe to run with my credentials right now”, and star counts are actively misleading (the most-starred servers score worst on quality in independent research). audit resolves what's installed against the official registry and scores it; every score drops back to provisional on a version bump, the direct fix for a server that ships clean for months then turns malicious in one release.

Streamingevery dialect, every surface

A slow answer and a broken one look identical.

Until they start arriving. Hydra renders an answer while the model is still writing it: in the terminal, in the hyctl tui cockpit, in the desktop app, and across a swarm. Seven executor paths stream natively: the OpenAI-compatible wire shape and Azure, Anthropic, Gemini, Cohere, Bedrock over its binary event stream, Ollama, and the agy CLI.

A model that cannot stream is not a second code path. Its whole output is delivered as one delta, so every surface is written once and the two kinds cannot drift apart in how they render.

$ hyctl dispatch "summarise this contract…"
ollama/qwen3:8b · writing…
⤺ abandoned openrouter/gpt after ~212 chars: 429 rate limited
   hyctl trace view run-7f2a --span 9c1d4e02

When the router falls back mid-answer, the abandoned partial does not sit there pretending to be the answer. It collapses to one line naming the model, roughly how much it wrote and why it stopped, and expands if you want to read it. The trace command appears only when payload capture is on, because without it the span stores no text and pointing you at an empty page would be worse than saying nothing.

FAQthe questions people actually ask

Straight answers.

What is Hydra?

Hydra is an open source gateway for AI models. For each request it picks the model best suited to that kind of task. It can also check the answer, and ask another model when the check fails. It works with hosted APIs, local models and CLI agents from any provider, and runs as a desktop app, a command-line tool (hyctl) and an OpenAI-compatible endpoint.

How does Hydra check an answer?

Every model and every checker, such as a test suite, a validator or a grounding check, gets a measured record of how often its verdicts turn out right for each task type. When you set a target, for example 95% with hyctl dispatch --confidence 0.95, Hydra combines their verdicts in a sequential probability ratio test (SPRT) and stops as soon as the probability that the answer is correct crosses it. If the answer cannot get there, Hydra asks the next-best model. hyctl trust calibration shows the measured records.

How does Hydra keep costs down?

With a target set, it stops as soon as the answer is checked, so it does not pay for models it does not need, and it can send work to a free local model when that model has a good record on the task type. Every request is logged with its cost, and hyctl stats shows where the money went. Hydra does not quote a savings percentage, because the saving depends on your tasks and your models. hyctl trace evaluate estimates it from your own logs.

How do I install Hydra?

The desktop app is a download for macOS, Windows and Linux from the desktop app page. The command-line tool, hyctl, installs with Homebrew: 'brew install ankit373/hydra/hyctl'. It is also available via npm ('npm install -g hyctl'), npx ('npx hyctl'), pip ('pip install hyctl'), a standalone installer ('curl -fsSL https://raw.githubusercontent.com/ankit373/hydra/main/install.sh | sh'), or prebuilt binaries from GitHub releases. Install Ollama too if you want to run models locally.

What models does Hydra support?

Any model you can reach: hosted APIs that speak the OpenAI, Anthropic, Gemini, Cohere, Bedrock or Azure formats, OpenRouter, local servers such as Ollama and llama.cpp, and CLI agents installed on your machine. hyctl probe finds what is already there. Add a model with 'hyctl models add' or by editing registry/models.yaml, with no code changes.

What is a swarm request?

A swarm sends one prompt to several models at once. Race mode returns the first successful answer, best mode asks a judge model to pick the strongest one, and all mode returns every answer for comparison. Run it with: hyctl dispatch --swarm --swarm-mode race 'your prompt'.

Does Hydra work without internet?

Yes, with a local model. Routing, logging and cost tracking run entirely on your machine, and when hosted APIs are unreachable or over budget Hydra falls back to a local model, for example one served by Ollama. Only calls to hosted models need the network.

Does Hydra stream model output as it arrives?

Yes, on every surface. An answer renders while the model is still writing it: in the terminal, in the hyctl tui cockpit, in the desktop app and across a swarm. Seven executor paths stream natively: the OpenAI-compatible wire shape and Azure, Anthropic, Gemini, Cohere, Bedrock over its binary event stream, Ollama, and the agy CLI. A model that cannot stream is not a separate code path: its whole output is delivered as one delta, so every surface is written once. When the router falls back mid-answer, the abandoned partial collapses to one line naming the model, how much it wrote and why it stopped, rather than staying on screen as if it were the answer.

What data leaves my machine when I use Hydra?

Only the prompt you send, and only to the model that answers it. There is no account, no server and no telemetry. Spend logs, run logs, the calibration record and the verified example corpus all stay in ~/.hydra on your own disk. An egress gate refuses to send a file classified as secret, such as .env or ~/.aws/credentials, to any model outside your machine, and a local-only policy pins sensitive work to models running on your hardware. Traces go to an OpenTelemetry collector only when you pass --otlp with an endpoint.

Can Hydra route between local models like Ollama and llama.cpp?

Yes. Hydra lists each model a running Ollama server offers, and each model a llama.cpp server has loaded. It identifies llama.cpp from the server's own build_info rather than assuming from the port, so an unrelated service on 8080 is not mistaken for one. A LiteLLM proxy is listed as one entry per model it fronts, and whether each counts as local is decided from the upstream the proxy reports rather than from its address, because a proxy on localhost forwarding to OpenAI is the normal deployment. hyctl models pull fetches a model into the local Ollama server, including a HuggingFace GGUF repo, without leaving hyctl.
