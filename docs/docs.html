Documentation

Every Hydra command — what it does, how it works (the logic and the calculation), and how to use it. The deep derivations live on First Principles. Everything here runs through the single hydra binary.

install one binary, no runtime

Hydra is pure Go — a single static binary. Homebrew is the shortest path; a standalone installer and source build also work.

Usage
# Homebrew (recommended)
brew install ankit373/hydra/hydra

# Standalone installer
curl -fsSL https://raw.githubusercontent.com/ankit373/hydra/main/install.sh | sh

# From source (Go 1.22+)
git clone https://github.com/ankit373/hydra.git
cd hydra && go build -o hydra ./cmd/hydra

hydra init first-run wizard

Scans your machine, ranks every model it finds, and walks you through picking a Cortex (your orchestrator), a local Ollama model calibrated to your real hardware, and whether you handle sensitive data.

How it works

Runs probe across three channels, reads 7 days of memory history to recommend a local model that fits your actual free RAM (75th-percentile, not total), and writes ~/.hydra/config.toml. Takes ~60 seconds.

Usage
hydra init

hydra probe discover every head

Concurrent machine scan that finds every available head and assigns each a CapScore — in under two seconds.

How it works

Three scanners run in parallel: PATH (13+ CLI agents — Claude Code, Codex, Cursor…), env vars (14 API providers via their keys), and ports (Ollama 11434, LM Studio 1234 — queried and enumerated model-by-model). Results are de-duplicated and ranked by CapScore.

Usage
hydra probe

hydra status live system state

Shows discovered heads, budget bars, and the rate-aware budget governor.

How it works

Beyond a static "you're at 58%" band, the governor models the orchestrator's context usage as a drifting process and estimates the first-passage probability of crossing the 80% ceiling before the task ends — so it escalates before a threshold is hit, not after. Reads logs/state.json history.

Usage
hydra status

hydra tui interactive cockpit

A terminal cockpit you can operate. Tab cycles three views; type a task and press enter to dispatch.

How it works

chat + code shows the live routing decision (classify → tier → head → fallback → cost saved) with a snippet streamed as the chosen head "writes." dashboard shows per-head sparklines, cost saved vs your priciest head, last confidence, and a band-colored governor gauge. agent-tree is the supervision tree with A2A handoffs and ↑/↓ node inspection.

Usage
hydra tui
hydra tui --snapshot --view 1   # render one static frame (docs / preview)

hydra dispatch the router

Routes a prompt to the cheapest head that clears the bar, with automatic fallback. This is the core command; everything else supports it.

How it works — the pipeline

1 · Classify the task to an enum key (or take --enum/--tier). 2 · Policy gate — PII detection can block a network call before it happens. 3 · Select the highest-CapScore available head at or under the target tier. 4 · Execute via the native executor (agy / Ollama / HTTP / CLI). 5 · On failure, fall down the chain — terminating at local Qwen, which never runs out. 6 · Log tokens and cost to cost.jsonl. The whole decision adds ~1.1µs.

Usage
hydra dispatch --prompt "refactor auth middleware to JWT refresh"
hydra dispatch --enum SIMPLE --prompt "write a User DTO"
hydra dispatch --dry-run --prompt "add pagination"   # preview the chain
hydra dispatch --local --prompt "write unit tests"    # no API calls
Key flags
--enum SIMPLE|STANDARD|… --tier N (pin a tier) --dry-run preview chain --local local-only --file raise bar by blast radius --a2a handoff.json --system system prompt

dispatch --swarm fan out, keep the best

Fan one prompt to several heads at once and keep the best answer.

How it works

race — first success wins (latency). best — an LLM judge picks the strongest answer. all — every answer, ranked by CapScore. A pre-flight --swarm-max-cost guard aborts if the fan-out would exceed your budget.

Usage
hydra dispatch --swarm --swarm-mode best "implement a rate limiter"
  --swarm-heads agy,gemini      # explicit heads (bypass tier)
  --swarm-max-heads 5           # cap fan-out
  --swarm-max-cost 0.05        # USD guard
  --swarm-judge-tier 1         # who judges in 'best'

dispatch --confidence route to a P(correct)

Instead of a fixed number of models, sample adaptively until a target confidence of correctness is reached — then stop.

How it works — the calculation

Runs a sequential probability ratio test (SPRT): it accumulates the calibrated log-likelihood ratio across votes and stops the moment it crosses the boundary implied by your target. Cheap on easy tasks, more sampling only where accuracy demands it. Add --file and the blast radius raises the bar automatically.

Usage
hydra dispatch --confidence 0.95 --prompt "is this migration safe for prod?"
hydra dispatch --confidence 0.90 --file internal/auth/token.go "rotate the signing key"

hydra trust the confidence layer

Builds and inspects the calibration that powers --confidence. Each source earns a measured reliability from real outcomes.

How it works — the calculation

Each source gets a Beta-Bernoulli posterior over sensitivity and specificity, which becomes a per-vote log-likelihood ratio and a diagnostic power D (KL divergence, in nats). A coin-flip source has D≈0 and is ignored; a proven one lets a single vote go far. The defect-cost model prices a wrong answer and sets the required confidence.

Subcommands
hydra trust calibration      # per-source se / sp / D table
hydra trust record --source model:claude --domain go --said-correct --outcome correct
hydra trust defect --pii --production   # modeled $ cost of shipping a defect
hydra trust stats            # samples saved vs fixed-N; achieved vs target
hydra trust explain <hash>   # the full LLR ledger for a past run
hydra trust benchmark        # measured SPRT numbers (deterministic seed)
See diagnostic power D derived →

hydra graph blast how dangerous is this file?

Reads a code dependency graph and reports a file's blast radius — and the confidence a change to it demands.

How it works — the calculation

From graph.json it counts transitive dependents and computes the percolation number κ = ⟨k²⟩/⟨k⟩ (Molloy–Reed). When κ ≥ 2 the file sits in a cascade-capable core, so its confidence bar is lifted — an edit to a hub everything imports must be far surer than a leaf helper.

Usage
hydra graph blast internal/auth/token.go
Drag the percolation threshold →

hydra graph parallel how many agents?

Given a set of files, returns the optimal number of parallel agents.

How it works — the calculation

Amdahl's law plus a coordination cost that grows with agent count: minimizing T(n)=s+(1−s)/n+kn gives n*=√((1−s)/k), where k comes from graph coupling. Independent files → ~6 agents; tightly-coupled edits → ~2. More is slower.

Usage
hydra graph parallel internal/a.go internal/b.go
See the speedup curve →

hydra context entropy signal, not length

Measures a context's information density and tells you when to compact.

How it works — the calculation

Signal density ρ = |gzip(C)| / |C| proxies the entropy rate; useful = L·ρ. Compact on falling ρ (stale, repetitive context) rather than on raw length — a dense 100k window beats a noisy 1M one.

Usage
hydra context entropy internal/foo.go
cat notes.md | hydra context entropy -

hydra mcp accountability ledger

A local, append-only ledger that records — and can gate — what every agent is allowed to touch and did.

How it works

A glob allow/deny policy decides each access (and records the decision). Every read/write event is appended to a local log you can audit — no data leaves your machine.

Subcommands
hydra mcp check <tool> --agent A --resource R --action write
hydra mcp record …          # append an access event
hydra mcp log --denied        # what got blocked
hydra mcp report            # allowed / denied by agent and tool

hydra oracle verify tests as evidence

Turns a verifier (tests, compiler, linter) into a first-class evidence source whose verdict can outweigh a model's opinion.

How it works — the calculation

Runs the command; exit 0 = pass. That verdict maps to a calibrated LLR — a high-D source — that feeds the same confidence math as model votes. A green test suite is strong, cheap evidence.

Usage
hydra oracle verify go test ./... --source verifier:go-test

hydra models runtime registry

Add a model at runtime — no rebuild.

How it works

Built-in scores live in embedded data.json; your additions merge over them via a runtime overlay at ~/.hydra/models.json, picked up on the next probe/dispatch.

Tiers & CapScore how routing decides

Every head gets a CapScore (0–100) from its capability profile; tasks route through named tiers by score. Lower tier number = stronger head.

The ladder
expert    90–100   Claude Opus, Claude Code
complex   80–89    Codex, GPT-class, Gemini Pro
standard  70–79    Gemini Flash, Claude Haiku
simple    60–69    Qwen3 8B, Qwen2.5-Coder 7B (local)
local     50–59    Llama 3.2 3B, Phi-4 Mini

Fallback chains never a dead end

If the chosen head is unavailable or rate-limited, Hydra falls to the next head in the chain automatically — terminating at local Qwen, which runs on your machine and is always available.

You never retry by hand. Preview any chain with hydra dispatch --dry-run.

PII policy / local-only enforced, not conventional

With local-only policy enabled, any prompt containing sensitive data is blocked from leaving your machine — at the dispatch layer, before any network call.

Detected patterns

SSNs, credit-card numbers, emails, API keys/tokens, IP addresses, private-key material. A matching prompt is re-routed to a local head instead of an API.

Budget governor spend attention wisely

Keeps every model — and the orchestrator itself — under its context ceiling.

How it works

Static pressure bands (normal → compact → caution → warning → critical → emergency) downgrade tiers as usage climbs. On top of that, a rate-aware first-passage model watches the burn rate and escalates before a threshold is crossed. The terminal fallback is always the free local head.

Bands
0–49%   normal      full orchestration
50–64%  compact     compact recommended
65–69%  caution     compact urgently
70–74%  warning     downgrade one tier
75–79%  critical    routing only
80%+    emergency    route to local, warn

A2A handoffs causal, conflict-aware

When work passes between agents, Hydra carries a structured handoff with a vector clock for causal ordering.

How it works

Vector clocks establish happens-before / concurrent relationships; two concurrent handoffs that touch overlapping files are flagged as a conflict. The last handoff is saved to logs/last_handoff.json and replayed with --a2a.

The math why the router isn't vibes

Six results run the router: Wald's SPRT, calibration diagnostic power (KL), the Bayes defect-cost bar, Molloy–Reed percolation-κ, Amdahl optimal parallelism, and context entropy. Each is stated, derived, and made interactive.
