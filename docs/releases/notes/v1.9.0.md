## Summary

Hydra 1.9.0 is about checking answers. You can ask it to check almost any kind of work: a label, an extraction, a summary, a support reply, a list of links or citations. When a check fails, the request reruns once on a stronger model. Prompt caching now shows up in the cost of every call, and the terminal app starts in Ask, so a first request never writes a file.

## Highlights

### Checking answers
- `--check` can now check a label against the label set, an extraction's fields and types, each sentence of an answer against its source, the links an answer cites, and DOIs and arXiv ids (#1705, #1816, #1826, #1946, #1959).
- `--check gen` writes checks for the kind of work you name with `--kind`, using a model from another family than the one that answered (#1834, #1784).
- `--check 'sum:total=items[].amount'` adds up the parts of a receipt or invoice and compares them with the total, with no model call (#1932).
- `--schema invoice.schema.json` uses your JSON Schema as the field list for the extraction check, so no model is asked to write one (#1938).
- `--source-only` answers only from the documents you give it, or says they do not cover the question (#1934).
- `--require-pass` turns the result into an exit code: 0 passed, 1 a check failed, 2 a check could not run, so a script or CI job can gate on it (#1926).
- Every verdict is kept in one log, so `hyctl trust` can show which checks pass wrong answers and when a model's record drops or recovers (#1555, #1714, #1928).

### Routing
- A failed check reruns the request once on a model measured stronger at that kind of work, and that model sees the failed answer and the reason (#1812, #1748).
- `--kind` names the kind of work, such as `summary` or `extraction.invoices`, and routing ranks models on their record for it (#1568).
- Workflow steps can name a check, run at the same time when they do not depend on each other, and never write the same file together (#1824, #1778, #1806).
- `hyctl compare A B --kind K` puts two models side by side from the record (#1936).

### Cost
- Cached prompt tokens are counted for OpenAI-style APIs, Anthropic, Bedrock and Gemini, priced at their cache rates, and shown in cost rows, traces and OTLP (#1558, #1693, #1753, #1717).
- Prompt caching can be turned on from `policy.yaml` for every request (#1755).

### Privacy and security
- Redaction catches more secret formats, including JSON keys, env lines and common vendor keys (#1931).
- Validators, oracles and checks run with a short list of environment variables, so a check never sees your API keys (#1718).
- Security hardening for serve, validators and the upgrade path. Details will be published as GitHub advisories.

### Terminal app
- The terminal app starts in Ask, which answers and never writes. Auto is one shift+tab away (#1744).
- The route line names the kind of work, the code panel shows only when a task touches a file, and a model's drop and recovery show up as they happen (#1747, #1749, #1965).

### Serving API
- A request to `hyctl serve` can name a check in `X-Hydra-Check` and read the verdict back in `X-Hydra-Check-Result` (#1967).

## Upgrade notes

- `hyctl serve` now checks every request. The `Host` header must be the address the server is bound to, a request with an `Origin` header is refused unless `--allow-origin` lists it, and a POST must send `Content-Type: application/json` (anything else gets 415). `max_cost_usd` in `policy.yaml` now caps every request, not only those that send `X-Hydra-Max-Cost-USD`. `--max-inflight` (default 8) and `--rate` (default 120 a minute) cap requests, with a 429 and `Retry-After` over either (#1719).
- The installers (`install.sh`, `install-app.sh`, `install.ps1`, npm and pip) stop when they cannot check the download's checksum, where they used to warn and carry on. Set `HYDRA_INSECURE=1` to keep the old behaviour (#1726).
- `hyctl upgrade` no longer runs `install.sh`. It downloads the release itself, refuses to install if the checksum is missing or does not match, and checks build provenance when `gh` is installed and signed in (#1720).
- Validators, oracles, `--check cmd:` and `hyverify` no longer inherit your whole environment. If a check needs a variable, add it under `validator_env:` in `workspace.yaml`, or pass `hyverify --env NAME`. Names that look like credentials are refused (#1718).
- The terminal app starts in Ask instead of Auto. Press shift+tab to switch (#1744).
- `hyctl oracle ground` exits 1 when a claim is unsupported and 2 when nothing could be checked (#1745).

## Security

This release includes security hardening for serve, validators and the upgrade path. Details will be published as GitHub advisories, and this page will link them once they are public.
